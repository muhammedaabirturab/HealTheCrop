# API Documentation

Interactive, always-up-to-date docs are auto-generated by FastAPI at `/docs` (Swagger UI)
and `/redoc`. This page is a curated reference for the endpoints and auth flow.

Base URL: `http://localhost:8000/api/v1` (dev) — see [Deployment Guide](deployment.md) for
production URLs.

## Authentication

JWT bearer tokens. Register once, then log in to receive an access token; send it as
`Authorization: Bearer <token>` on every subsequent request.

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/auth/register` | — | Create a farmer/admin account |
| POST | `/auth/login` | — | Returns `access_token` + `refresh_token` |
| GET | `/auth/me` | ✅ | Current user profile |

**Example:**
```bash
curl -X POST http://localhost:8000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"name":"Farmer Rao","email":"rao@example.com","password":"secret123","location":"Karnataka"}'

curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"rao@example.com","password":"secret123"}'
```

## Sensors

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/sensors/ingest` | — (device-authenticated by `device_uid`) | ESP32 posts a reading; auto-registers unseen devices |
| GET | `/sensors/devices` | ✅ | List all devices |
| GET | `/sensors/devices/{device_uid}/latest` | ✅ | Latest reading for a device |
| GET | `/sensors/devices/{device_uid}/history?limit=100` | ✅ | Historical readings |

## Crop Recommendation (ML)

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/predictions/manual` | ✅ | Predict from manually entered N-P-K/temp/humidity/pH/rainfall |
| POST | `/predictions/from-device` | ✅ | Predict from a device's latest sensor reading |
| GET | `/predictions/history?limit=50` | ✅ | Past predictions |

Response includes `recommended_crop`, `confidence`, `alternatives` (top-5 with per-crop
metadata), `feature_importance`, and full `crop_details` (image, season, water requirement,
harvest duration, soil suitability, expected yield).

## Pest & Disease Detection

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/pest/scan` | ✅ | Multipart image upload → detections |
| GET | `/pest/history?limit=50` | ✅ | Past scans |

Each detection includes `display_name`, `type` (disease/pest/healthy), `confidence`,
`description`, `organic_treatment`, `chemical_treatment`, `recommended_pesticides`,
`prevention_tips`, `expected_recovery_days`, and a bounding-box `region` when available.

## Error format

Standard FastAPI error shape: `{"detail": "message"}` with the appropriate HTTP status
(400 validation, 401 unauthorized, 403 forbidden, 404 not found, 422 request validation).
